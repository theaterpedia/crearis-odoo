## Core Issue Discovered: KursLookupId Mismatch

### The Problem
The `_build_participant_kurs_map()` method was returning **0 entries** despite 265 kursteilnehmer records:

```
Kursteilnehmer debug: {
  'total': 265, 
  'no_status': 0, 
  'invalid_status': 76, 
  'no_contact': 0, 
  'no_kurs': 0, 
  'kurs_not_found': 189,  ← ALL valid-status records fail here
  'matched': 0
}
```

### Root Cause
**`KursLookupId` in `plan_kursteilnehmer` references the `plan_kurse` list, NOT the `contacts` list directly.**

- Our code built `kurs_code_map` from contacts with `_`-prefixed FullName (IDs like 530, 532, 550, 512...)
- But `KursLookupId` values are 37, 22, etc. — IDs from the **separate `plan_kurse` list**
- These ID spaces don't match → 100% lookup failure

### Evidence
```
Kurs map: contact_id=530 → kurs_code=M18
Kurs map: contact_id=550 → kurs_code=Profil ZT 2026-2028
...
KursLookupId 37 not found in kurs_code_map (contact 267)
KursLookupId 22 not found in kurs_code_map (contact 282)
```

## Required Solution

To properly evaluate kursteilnehmer → kurs_level, we need to:

1. **Fetch `plan_kurse` list** from SharePoint
2. **Build mapping:** `plan_kurse.id` → `plan_kurse.ContactLookupId` (or similar field pointing to contacts)
3. **Resolve chain:** `kursteilnehmer.KursLookupId` → `plan_kurse` → `contacts` → Kurs code

### Data Model (as user explained)
```
plan_kurse
├── id: 37, 22, etc. (referenced by KursLookupId in kursteilnehmer)
├── maps to exactly one contact entry (the _-prefixed course product)
├── handles master-course → course-variation relations
└── used to configure events-schedule per course
```
